# RevoTask

RevoTask is a collaborative Kanban app for small teams. Members organize cards into columns, move cards through a workflow, assign work and discuss cards. Board admins manage membership and columns.

**Status:** Foundation (T01–T02), authentication (T03–T04), boards and membership (T05–T06), the Kanban columns and cards (T07–T09) card comments (T10), My tasks and board search (T11), and the profile (T12) are implemented locally. The Flask API (Docker image with Compose on port 5001) serves health, register, login, logout, the current-user read, the board and membership routes (E05–E12), the column and card routes (E13–E20) the comment routes (E23–E26), the read-only My Tasks and card search routes (E21–E22), and the profile update (E30–E31). Passwords use Argon2id, and JWT revocation and local rate limits are in place. Admins create, rename and delete boards and manage members. Removing a member clears that member's assignments on active cards in active columns of that board. Admins add, rename, reorder and delete columns and mark one Done column. Any participant adds, edits, assigns, deletes and moves cards, by desktop drag or by the Move button, which works with a keyboard or by touch. Moves are versioned: a stale move returns 409 and the board refetches. A card opens in a Card details dialog where any participant reads and adds comments, and only the author edits or deletes their own. If a post may have been saved while its response was lost, the dialog refreshes the list and says so before you retry. The Next.js app has `/register`, `/login`, a dashboard at `/`, board pages at `/boards/[id]` a My tasks page at `/my-tasks` and a Profile page at `/profile`, where you change your name or email (only changed fields are sent, a taken email shows an error under Email, and you stay signed in after an email change). The board page has a Search cards field (300 ms debounce, up to 20 results, results follow the live board), and the header links Boards and My tasks at every width. The session is in an HttpOnly cookie. The register password needs 8 to 128 characters with an uppercase letter, a lowercase letter and a special character. Local checks: backend 1907 tests passed and 1 skipped, with ruff clean. Frontend typecheck and lint are clean, 1845 Vitest tests in 88 files pass, and `next build` succeeds. The boards screens passed a 180-check Chrome run (device emulation), the kanban screens passed a 418-check run, the comments screens a 480-check run, the My tasks and search screens a 359-check run, and the profile screens a 376-check run, at 320, 375, 768 and 1280 px with scripted 375 px journeys. Authentication also has a 75-check HTTP smoke and a 96-check Chrome run (device emulation, no real phone). The UI follows one dashboard design system ([frontend guidelines](guidelines/frontend.md), FE-D1 to FE-D9): a sidebar from 1024 px and a top bar below it. Pending: real-device and on-screen-keyboard checks, a pointer drag in Playwright (T15), live deployments and submission evidence. Production rate limiting needs shared storage and trusted client address handling before release (T16). Adding members and changing a profile email can reveal whether an email is registered to a user, a risk accepted for v1. Reauthentication for an email change, new-address confirmation, an old-address notice and an E31 rate limit are tracked in T16. Results: [foundation evidence](evidence/foundation-T01-T02.md), [authentication evidence](evidence/authentication-T03-T04.md) [boards and membership evidence](evidence/boards-membership-T05-T06.md), [kanban evidence](evidence/kanban-T07-T09.md) [comments evidence](evidence/comments-T10.md) [My tasks and search evidence](evidence/my-tasks-search-T11.md) and [profile evidence](evidence/profile-T12.md).
