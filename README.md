# RevoTask

RevoTask is a collaborative Kanban app for small teams. Members organize cards into columns, move cards through a workflow, assign work and discuss cards. Board admins manage membership and columns.

**Status:** Foundation (T01–T02), authentication (T03–T04), boards and membership (T05–T06), the Kanban columns and cards (T07–T09) and card comments (T10) are implemented locally. The Flask API (Docker image with Compose on port 5001) serves health, register, login, logout, the current-user read, the board and membership routes (E05–E12), the column and card routes (E13–E20) and the comment routes (E23–E26). Passwords use Argon2id, and JWT revocation and local rate limits are in place. Admins create, rename and delete boards and manage members. Removing a member clears that member's assignments on active cards in active columns of that board. Admins add, rename, reorder and delete columns and mark one Done column. Any participant adds, edits, assigns, deletes and moves cards, by desktop drag or by the Move button, which works with a keyboard or by touch. Moves are versioned: a stale move returns 409 and the board refetches. A card opens in a Card details dialog where any participant reads and adds comments, and only the author edits or deletes their own. If a post may have been saved while its response was lost, the dialog refreshes the list and says so before you retry. The Next.js app has `/register`, `/login`, a dashboard at `/`, and board pages at `/boards/[id]`. The session is in an HttpOnly cookie. The register password needs 8 to 128 characters with an uppercase letter, a lowercase letter and a special character. Local checks: backend 1706 tests passed and 1 skipped, with ruff clean. Frontend typecheck and lint are clean, 1571 Vitest tests in 75 files pass, and `next build` succeeds. The boards screens passed a 180-check Chrome run (device emulation), the kanban screens passed a 418-check run, and the comments screens a 480-check run, at 320, 375, 768 and 1280 px with scripted 375 px journeys. Authentication also has a 75-check HTTP smoke and a 96-check Chrome run (device emulation, no real phone). The UI follows one dashboard design system ([frontend guidelines](guidelines/frontend.md), FE-D1 to FE-D9): a sidebar from 1024 px and a top bar below it. Pending: real-device and on-screen-keyboard checks, a pointer drag in Playwright (T15), live deployments and submission evidence. Production rate limiting needs shared storage and trusted client address handling before release (T16). Adding members can reveal whether an email is registered to a user, a risk accepted for v1. Results: [foundation evidence](evidence/foundation-T01-T02.md), [authentication evidence](evidence/authentication-T03-T04.md) [boards and membership evidence](evidence/boards-membership-T05-T06.md), [kanban evidence](evidence/kanban-T07-T09.md) and [comments evidence](evidence/comments-T10.md).
