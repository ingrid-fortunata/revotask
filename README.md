# RevoTask

RevoTask is a collaborative Kanban app for small teams. Members organize cards into columns, move cards through a workflow, assign work and discuss cards. Board admins manage membership and columns.

**Status:** Foundation (T01–T02), authentication (T03–T04), boards and membership (T05–T06), the Kanban columns and cards (T07–T09) card comments (T10), My tasks and board search (T11), the profile (T12), notifications (T13) and board analytics (T14) are implemented locally, and local acceptance (T15) has passed. The Flask API (Docker image with Compose on port 5001) serves health, register, login, logout, the current-user read, the board and membership routes (E05–E12), the column and card routes (E13–E20) the comment routes (E23–E26), the read-only My Tasks and card search routes (E21–E22), the profile update (E30–E31) the notification routes (E27–E28) and the read-only board analytics route (E29). Passwords use Argon2id, and JWT revocation and local rate limits are in place. Admins create, rename and delete boards and manage members. Removing a member clears that member's assignments on active cards in active columns of that board. Admins add, rename, reorder and delete columns and mark one Done column. Any participant adds, edits, assigns, deletes and moves cards, by desktop drag or by the Move button, which works with a keyboard or by touch. Moves are versioned: a stale move returns 409 and the board refetches. A card opens in a Card details dialog where any participant reads and adds comments, and only the author edits or deletes their own. If a post may have been saved while its response was lost, the dialog refreshes the list and says so before you retry. The Next.js app has `/register`, `/login`, a dashboard at `/`, board pages at `/boards/[id]` a My tasks page at `/my-tasks` and a Profile page at `/profile`, where you change your name or email (only changed fields are sent, a taken email shows an error under Email, and you stay signed in after an email change). The board page has a Search cards field (300 ms debounce, up to 20 results, results follow the live board), and the header links Boards and My tasks at every width. A notification bell in the header shows your unread count (a `99+` cap, the exact count in its name) and refreshes every 30 seconds. A new assignment, or a new comment on a card assigned to you, from another user creates a notification in the same transaction. The bell opens a Notifications dialog with board links, Newer and Older paging and a Mark as read button, and notifications for a board you can no longer access are hidden and return if your access does. An Analytics button at the right end of the board header opens a dialog with, for the current UTC week (Monday to Sunday), the cards completed (each card once, even if it re-enters Done or is deleted later), the card count per column and the activity per member (cards created or moved, columns reordered and comments, former members included). It reads when the page opens, after your own card or column change and on Refresh, does not poll, and keeps any error inside the panel so the board stays usable. The session is in an HttpOnly cookie. The register password needs 8 to 128 characters with an uppercase letter, a lowercase letter and a special character. Local checks: backend 2058 tests passed and 1 skipped, with ruff clean. Frontend typecheck and lint are clean, 2039 Vitest tests in 98 files pass, and `next build` succeeds. The boards screens passed a 180-check Chrome run (device emulation), the kanban screens passed a 418-check run, the comments screens a 480-check run, the My tasks and search screens a 359-check run, the profile screens a 376-check run the notification screens a 205-check run and the analytics screens a 128-check run, at 320, 375, 768 and 1280 px with scripted 375 px journeys. Authentication also has a 75-check HTTP smoke and a 96-check Chrome run (device emulation, no real phone). The UI follows one dashboard design system ([frontend guidelines](guidelines/frontend.md), FE-D1 to FE-D9): a sidebar from 1024 px and a top bar below it. ## Deployment

- **Web (Vercel):** Root Directory `frontend`. Every push to `main` deploys automatically.
- **API (Render):** Docker, Root Directory `backend`. Auto-Deploy is off. `.github/workflows/deploy-backend.yml` runs on each push to `main` that changes `backend/`: it runs `flask db upgrade` on Supabase first, then triggers the Render deploy.
- **Database:** Supabase, schema `revotask`, separate migration and runtime roles.

Full runbook, environment values and current deviations: [deployment runbook](docs/DEPLOYMENT.md).
