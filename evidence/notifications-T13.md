### Findings from the browser run

| ID | Finding | Cause | Fix and check |
| --- | --- | --- | --- |
| F-NT-1 | At 320 and 375 px the bell overlapped the Profile link. | The brand block was `flex-1 min-w-0`, so it shrank below its content instead of letting the row wrap. At 320 px the five controls cannot fit one row with the wordmark and a 28vw name. | The brand block is `flex-auto`. The account name is `max-w-[18vw]` below 640 px. The wordmark is visually hidden below 400 px and stays the link's accessible name. Rerun: no overlap, 108 px header (two rows) at 320 and 375 px. FE-D2 records it. |
| F-NT-2 | The panel heading and row text were almost invisible. | The dialog renders inside the dark header and inherited its pale text color. Numeric checks did not catch it; the screenshot did. | The panel content has `text-base-content`. The script now also checks the heading's computed color. |
| F-NT-3 | A long unbroken title ran under the Unread badge. | A `flex` link item does not break a long word with `break-words`. The first width check passed because the dialog box clipped the overflow. | The text sits in a span with `overflow-wrap: anywhere`. The script now checks each row for overflow and for a link and badge overlap. |
| F-NT-4 | Script artifacts, not app defects: boxes measured during the dialog's entry transition (43.1 instead of 44 px, and hit tests that missed), focus not returning, and Tab starting after the bell. | The script measured before the transition ended, clicked the bell with `element.click()` (which does not focus it), and Tab continued from Chrome's focus starting point. | The script waits 500 ms after opening, focuses the bell before clicking and reloads before the Tab test. |
