# RevoTask Requirements · Baseline 0.4.0

Each AC is independently verifiable. The [traceability matrix](traceability.md) maps ACs to the API/UI, tasks and planned verification. All implementation and test results are pending.

| ID / user story | Acceptance criteria |
|---|---|
| R01 · As a visitor, I can create an account. | **AC01.1** When I submit valid name, email and password, the API creates the account, returns 201 without password fields, and the UI sends me to login. **AC01.2** Invalid input returns field-level 400 errors. A repeated normalized email returns 409 even for concurrent registrations. |
| R02 · As an account holder, I can start and end a session. | **AC02.1** Valid credentials open the dashboard and the Flask API issues an expiring JWT. **AC02.2** Invalid credentials show a generic error. Missing, expired or revoked authentication on a protected route returns 401 and private UI redirects to login. **AC02.3** Logout clears the browser session, revokes the JWT and prevents access through back navigation or token replay. |
| R03 · As a participant, I can manage and open accessible boards. | **AC03.1** Creating a board makes me its admin. Dashboard returns only boards I own or belong to. **AC03.2** Board detail returns active columns and cards in deterministic order. **AC03.3** The admin can rename/delete the board. A nonmember cannot read or mutate it and receives the same 404 as for a missing board. A deleted board returns 404. |
| R04 · As an admin, I can manage board membership. | **AC04.1** I can add a registered user by email and view board participants. An unregistered email returns 404 `USER_NOT_FOUND` to the board admin. **AC04.2** Removing a member revokes their board access and clears their assignments on active cards in active columns of that board atomically. Soft-deleted cards, cards in soft-deleted columns and other boards keep their data. The board admin remains a participant. |
| R05 · As an admin, I can organize workflow columns. | **AC05.1** Admins can add, rename and remove columns. A column with active cards must be emptied before deletion or changing its Done flag. Only one active Done column is allowed per board. **AC05.2** Admins can reorder columns and see the new order after reloading. |
| R06 · As a participant, I can create, edit, assign and remove cards. | **AC06.1** I can create, edit and soft-delete a card. Assignments are limited to active board participants and can be cleared. **AC06.2** My Tasks shows my active assignments from accessible boards, grouped by board, with an empty state. |
| R07 · As a participant, I can change a card’s position. | **AC07.1** A card can move within or across columns on the same board. Desktop drag and the Move control persist identical behavior. **AC07.2** The board updates optimistically. A failed move restores the prior order and shows feedback. A stale version returns 409 and refreshes server state. Cross-board destinations fail without any mutation. A move to the card's current place changes neither the order nor the version. |
| R08 · As a participant, I can discuss a card. | **AC08.1** The modal shows comments and accepts valid content. Missing or blank content returns 400. **AC08.2** Only the comment author with current board access can edit/delete it. A successful edit updates `updated_at`. |
| R09 · As a participant, I can find cards. | **AC09.1** Board search matches title text within the active board after a 300 ms debounce. Stale results cannot overwrite newer queries. Empty and no-result states are distinct. |
| R10 · As a user, I can see and acknowledge notifications. | **AC10.1** A new assignment or a new comment on my assigned card from another user creates an in-app notification in the same transaction. The bell shows the total unread count and refreshes every 30 seconds while mounted. **AC10.2** I can page through and mark my notifications read. Notifications for boards I can no longer access are excluded. |
| R11 · As a participant, I can understand board activity. | **AC11.1** Analytics shows active card count per active column, distinct cards entering Done in the current UTC week, and event counts by actor for that week. Empty boards show zeros or an empty list as applicable. |
| R12 · As an account holder, I can update my profile. | **AC12.1** Profile reads and updates my name and email, with feedback and no password fields in any response. Password-change fields are rejected with 400. |
| R13 · As a user, I can use the app reliably. | **AC13.1** Every page, dialog and control works at 375 px and wider with no horizontal page scroll outside the Kanban region, touch targets of at least 44 px and 16 px text inputs. The core flow completes at 375 px, and all movement has a keyboard/touch alternative. **AC13.2** Warm board detail meets the measured p95 target in the brief. **AC13.3** Authenticated responses are private/no-store. Cross-origin browser mutations are rejected. Secrets are excluded from source and browser bundles. |
| R14 · As an assessor, I can verify the running submission. | **AC14.1** Live Flask health, registration and login pass, and all eight Blueprints have public-API evidence with a test account. **AC14.2** The live UI passes auth and Kanban E2E journeys, including position persistence, and has a reproducible report and mobile evidence. **AC14.3** The repository includes reviewed docs, steering evidence, traceable specs and actual version history. |
