# Pages and Components

Next.js App Router pages render on the server and compose client components for interactive forms, browser hooks and drag-and-drop. Use Tailwind CSS with daisyUI, following the dashboard look in the Visual Design System of [frontend guidelines](../../guidelines/frontend.md) (FE-D1 to FE-D9). Show meaningful loading, empty, success and failure states on each data-driven surface.

| Route or surface | Component boundary | API and expected behavior |
|---|---|---|
| `/register` | Server page and client `RegisterForm` | E02. Exactly `name`, `email` and `password`, validated with the same rules as the API. The password field shows the rules (8 to 10 characters, an uppercase letter, a lowercase letter and a special character) as help text linked to the input. Controlled inputs, pending submit, inline validation, then redirect to login with the user still signed out. |
| `/login` | Server page and client `LoginForm` | E03. Exactly `email` and `password` (1 to 10 characters, no composition rule). Session cookie set by the Route Handler. Invalid credentials stay on the form. Successful login opens the dashboard, or a safe same-origin `next` path. |
| `/` | Protected Server Component with client create dialog | E05–E06. Show accessible board summaries or an empty state. |
| `/boards/[id]` | Protected Server Component with `KanbanBoard` client island | E07–E20, E22 and E29 as applicable. Show ordered columns and cards, member controls, board search, analytics and a touch/keyboard Move action. `CardSearch` (hook `useCardSearch`) debounces 300 ms, aborts superseded requests, ignores late responses, resolves results against the live board state and opens the card detail modal from a result. It does not use the Kanban gate. `AnalyticsPanel` (client, hook `useBoardAnalytics`, props-only `AnalyticsFigures`) sits below the Kanban region, reads E29 through a same-origin handler on mount, when the Kanban `position_version` rises and on Refresh (no polling), keeps its loading and error states inside the panel and does not use the Kanban gate. |
| Card detail modal | Client `CardDetailModal` (named "Card details", `BaseModal` with `wide`), `CardEditForm`, props-driven `CommentList`, `CommentItem`, `CommentForm` and the `useCardComments` hook | E18, E19 and E23–E26. It opens from the card's "Open <title>" button. Show comment loading, empty and error states with Retry, add, edit and delete with a confirmation, and Edit and Delete only on the current user's comments. Comment content is plain text with its line breaks. A 404 refetches the board and either leaves, closes the modal or reloads the comments. An uncertain add keeps the draft and the list, refetches, and enables a manual retry only after the refresh. Restore focus when closed. |
| `/my-tasks` | Protected Server Component with client `MyTasks` (search state) and props-only `TaskGroup` | E21. Group current-user assignments by board in the order the API returns them (case-insensitive board name, then board ID). The group heading and each row link to `/boards/<id>`, with no card deep link. Show a summary, the board chip color, a description excerpt, a status badge on each row (the column name, success style with a check icon for a Done column) and an empty state. A search field filters the loaded tasks by title in the browser with no request and no debounce, hides groups with no match, shows "N of M tasks" and a no-match state with Clear search, and keeps the query out of the URL. A read failure uses the error boundary. |
| `/profile` | Protected server page and controlled client `ProfileForm` | E30–E31. Seed from the safe user DTO (`getCurrentUser()`). Show the email read-only (it cannot be changed). Send the name only when changed and the password pair only when the user opened Change password and typed in it, through the same-origin `PATCH /api/users/me` handler. Show field errors inline (a wrong current password under Current password, section stays open), then on success reseed, empty and close the password section, call `setUser` on the safe user context, `router.refresh()` and toast "Profile updated.". Save is disabled while pristine or pending. The AppHeader account block links here. |
| Shared header | Client `AppHeader` with the Boards and My tasks links at every width (a second row of the top bar below 1024 px, the sidebar list from 1024 px), the `NotificationBell` at the right end of the brand block, and the account controls (Profile link and Sign out) | E04, E27–E28. The bell shows the exact unread count in its name, a badge hidden at 0 and capped at `99+`, and opens the Notifications `BaseModal` with board links, "Newer" and "Older" paging at 20 per page and a "Mark as read" button per unread row. Following an unread row's link marks it read without blocking navigation. Sign out and the account link are unchanged. |

The Kanban island is built from `KanbanColumn`, `AddColumnForm`, `ColumnEditDialog`, `CardDetailModal` (with `CardEditForm` and the comment parts) and `MoveCardDialog`, with the shared `SelectField` for selects and `CheckboxField` for the Done flag, and `FormField` with `multiline` for the description. `BoardCard`, `ColumnHeader` and `CommentList` are props-driven and server-compatible (`CommentItem`, which holds only the editor draft, and `CommentForm` are client components). They enter the client graph when imported by a client island. `AddCardForm` is a Client Component because it handles input and submission. Use `BaseButton`, `BaseBadge` and `BaseModal` for common controls. Keep focus indicators, labels, Escape behavior and focus return, and verify keyboard interaction.

| Hook | Responsibility |
|---|---|
| `useKanbanBoard` | Own the board state seeded from the server read. Run every Kanban write and refetch through one gate, so only one runs at a time. Provide the single `moveCard` function used by drag and the Move dialog: snapshot affected lists, apply the optimistic move, reconcile the server response, and roll back or refetch as specified in the error matrix. Queue a refetch requested during a pending write and discard a refetch response older than a later write. |
| `useDragAndDrop` | Hold desktop drag state and the drop targets (before a card, end of a column), and call `moveCard`. Keep no request logic. |
| `useNotifications` | Fetch on mount and poll every 30 seconds for the shown page (page 1 while the panel is closed). One E27 request at a time, one timer restarted by every request, a tick skipped while a request or a mark is pending. A response for an earlier page, or requested before a completed mark, is dropped. A background failure shows nothing and a foreground one (open, page change, Retry, the refresh after a mark) shows an error with Retry. Marking read is one request at a time: it lowers the badge, aborts any E27 in flight and refreshes the page. Clean up the timer and the request on unmount. |
| `useBoardAnalytics` | Read E29 on mount and when the board ID changes, again when the Kanban `position_version` rises above the version of the last read, and on Refresh. One request at a time, an earlier request is aborted, a late or earlier-board response is ignored, errors are held in the hook and the last figures are kept. No polling and no Kanban gate. |
| `useCardSearch` | Apply a 300 ms debounce, cancel or ignore stale requests, clear results for blank queries, and distinguish empty query from zero matches. Keep SearchBar.tsx focused on rendering and input events. |
| `useErrorHandler` | Map typed API errors to visible outcomes, using the [error handling matrix](error-handling.md). |

Every page, dialog and control follows FE-S4–S6: mobile-first classes, no horizontal page scroll outside the Kanban region, 44 px touch targets, 16 px inputs and `min-h-dvh`. Verify each surface at 320, 375, 768 and 1280 px, including a usable header, forms and touch Move controls. Test real card title/assignee and comment content using React Testing Library.
